RemoteCare workflow map

Patients and family caregivers use only WhatsApp. Doctors and physician assistants use a web dashboard. Gemini 3.8 handles all document reading, OCR, voice notes and AI summaries, and is only ever called by the backend.

System architecture

Every message from a patient or caregiver comes in as a WhatsApp webhook. The backend decides what the message is, calls Gemini when it needs to read a file or audio, saves the result, and runs the rules. Messages the platform starts itself (reminders, alerts) go out as approved templates.

Workflow 1

Doctor onboarding

Doctors and PAs work in the web dashboard. The only WhatsApp step is the patient’s opt-in, which WhatsApp requires before any business-initiated message.

  • Consent is stored with a timestamp and the template text that was shown. You need this for audits and for WhatsApp policy.
  • The patient pool is a product decision: import from the hospital system, referrals, or patients who message the clinic number first.

Workflow 2

Patient onboarding

The patient replied to the opt-in, so the 24-hour chat window is open. Free-form and interactive messages can be used without templates.

  • Gemini returns JSON that must match a fixed schema (drug, strength, dose, frequency, route; marker, value, unit, date, reference range). The backend rejects output that does not match.
  • Nothing extracted affects alerts until a PA or doctor approves it. The patient’s confirmation catches obvious errors but does not replace clinical review.
  • The caregiver is a separate WhatsApp contact with their own opt-in. Messages to them go only where the doctor allows.

Workflow 3

Home monitoring

Reminders are template messages because they usually arrive more than 24 hours after the last reply. The caregiver or patient can answer in whatever way is easiest for them.

  • A WhatsApp Flow form is the most reliable input. Free text, voice notes and device photos are accepted as fallbacks and always echoed back for confirmation.
  • Voice notes let caregivers report in their own language. Gemini transcribes and extracts in one call.
  • Medicine adherence can be a simple button list: each scheduled dose, marked [Taken] or [Missed].

Workflow 4

Insights and alerts

Threshold checks run in a plain rules engine, not in the AI model, so every alert can be traced to a number and a rule. Gemini only writes summaries.

  • Routing is set per patient by the doctor: who gets RED alerts, who gets AMBER, and the escalation timer.
  • Every WhatsApp alert to a caregiver should state that the service is not for emergencies and give the emergency number.

Workflow 5

Doctor intervention

The dashboard puts everything from Workflows 2–4 in one view for a remote review or a clinic visit. The doctor’s changes feed back into the monitoring plan.

  • RAG is colour plus a label (“High”, “Watch”, “OK”), so it is readable in print and for colour-blind users.
  • The AI-written brief and patient message are drafts. The doctor sees the source data next to them and approves before anything is sent.

Open decisions

  1. Health data and the Gemini API. Check the data-processing terms, data region and retention settings for health data where you operate (for example DPDP in India, HIPAA in the US). Vertex AI usually offers more control than the consumer API.
  2. WhatsApp access. Use Meta’s Cloud API directly, or go through a business solution provider that handles template approval and number setup.
  3. Languages. Decide which languages templates and replies support. Each language needs its own approved template.
  4. Emergencies. Decide what happens when a RED alert goes unanswered out of hours, and what the patient is told to do.
  5. Who can enter data. Decide whether the caregiver can enter readings for the patient, and how the record shows who entered each one.
